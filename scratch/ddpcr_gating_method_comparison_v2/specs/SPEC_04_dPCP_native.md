# SPEC 04: native dPCP

## Purpose

Run the full native `dPCP` workflow from package-compatible input files derived
from QuantaSoft JSONs, then compare against the earlier adapter.

## Evidence Basis

- `dPCP` vignette states that dPCP requires amplitude files and a nine-column
  sample table.
- The vignette explicitly recommends high-quality references for sensitive
  analyses, few positive partitions, and expected rain.
- Native dPCP identifies empty and single-target clusters in references with
  DBSCAN, predicts multi-target centroids by vector addition, uses fuzzy
  c-means, and reclusters rain with Mahalanobis distance.
- The package exposes both `dPCP()` and the stepwise native workflow.

## Reference Selection

For each assay/run:

1. Prefer matched same-run positive or high-quality reference controls.
2. If unavailable, use nearest assay-matched reference with identical assay,
   primers/probes, cycling, and channel orientation.
3. If no defensible reference exists, mark the job as reference unavailable.

All choices go to `tables/dpcp_reference_selection.csv`.

## Native Execution

Run both:

```r
results <- dPCP(
  file = sample_table,
  system = "bio-rad",
  file.location = input_dir,
  reference.quality = 0.5,
  sample.quality = 0.5,
  eps = chosen_eps,
  minPts = chosen_minPts,
  save.template = TRUE,
  rain = TRUE
)
```

and:

```r
sample.table <- read_sampleTable(...)
ref <- read_reference(...)
samp <- read_sample(...)
dbref <- reference_dbscan(...)
cent <- centers_data(...)
cmclus <- cmeans_clus(cent)
rainclus <- rain_reclus(cmclus)
quantcm <- target_quant(cmclus, sample.table)
quant <- target_quant(rainclus, sample.table)
rep.quant <- replicates_quant(quant, sample.table)
```

## Parameter Selection

Use `dbscan_combination()` on reference candidates to evaluate `eps` and
`minPts`. Start from package defaults (`eps = 200`, `minPts = 50`) and test a
small grid around them. Choose per assay/run based on reference cluster
separation and control validation, not sample positivity.

## E2E Checks

- `read_sampleTable()` succeeds.
- `read_reference()` succeeds.
- `read_sample()` succeeds.
- `reference_dbscan()` succeeds.
- `cmeans_clus()` succeeds.
- `rain_reclus()` succeeds or logs a native reason.
- `target_quant()` succeeds.
- Native dPCP output is converted into common-schema counts.
- Comparison to the previous adapter is generated.

## Failure Handling

A valid native dPCP run requires successful reference reading, sample reading,
reference DBSCAN, c-means, and quantification. If any step fails, retry only
with a documented alternate reference or parameter grid. Do not fall back to the
adapter while labelling the result native.
